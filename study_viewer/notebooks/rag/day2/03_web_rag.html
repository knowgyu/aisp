2. Implementing a Chunk Extractor

This time, we will define and use a Chunk Extractor. As you observed during the first practice session, the Chunk Extractor is a function needed to split the search results into appropriately sized pieces for use.

Since search results are essentially HTML files, we will first define the parse_htmls function to remove HTML tags. Then, we will define the extract_chunks function, which splits the text extracted from the HTML into chunks. To avoid losing information at the chunk boundaries, the text will be split at the sentence level.

Code Cell 008
1### YOUR CODE HERE ###2 3def parse_htmls(search_results):4    all_documents = []5 6    # Process each HTML text from the search results to extract text content.7    for html_text in search_results:8 9        # Parse the HTML content using BeautifulSoup10        soup = BeautifulSoup(html_text["page_result"], features="lxml")11        text = soup.get_text(" ", strip=True)  # Use space as a separator, strip whitespaces12        all_documents.append(text)13 14    return all_documents15 16def extract_chunks(all_documents):17    # Initialize a list to hold all extracted sentences from the search results.18    all_chunks = []19 20    for document in all_documents:21 22        if not document:23            # If no document is extracted, add an empty string as a placeholder.24            all_chunks.append("")25        else:26 27            # Extract offsets of sentences from the document28            _, offsets = text_to_sentences_and_offsets(document)29 30            # Initialize a list to store sentences31            chunks = []32 33            # Iterate through the list of offsets and extract sentences34            for start, end in offsets:35                # Extract the sentence and limit its length36                chunk = document[start:end][:MAX_CONTEXT_SENTENCE_LENGTH]37                all_chunks.append(chunk)38 39    return all_chunks

3. Implementing a Retriever

This time, we will implement a Retriever using the Chunk Extractor we defined earlier, without relying on AI frameworks like LlamaIndex.

For this implementation, the following components are required:

<br/>

  • Chunk extractor: Used to split the input search_results into chunks.
  • Embedding model: Used to generate embeddings for the chunks and the query.
  • Similarity metric: Measures the similarity between embeddings. We will use cosine similarity here.

Using these components, let’s implement the BaseRetriever with the following code:

Code Cell 013
1### YOUR CODE HERE ###2 3class BaseRetriever:4    def __init__(self,):5        self.client = openai.OpenAI(api_key = os.environ["OPENAI_API_KEY"])6 7    def embed_text(self, texts):8        """Generate embeddings using OpenAI's embedding model."""9        if isinstance(texts, str):10            texts = [texts]11 12        response = self.client.embeddings.create(13            model="text-embedding-3-small",14            input=texts15        )16 17        # Extract embeddings correctly from the response object18        embeddings = [np.array(item.embedding) for item in response.data]  # Adjust based on actual attributes19        return np.array(embeddings)20 21    def retrieve(self, query, search_results, topk):22        # Get documents23        all_documents = parse_htmls(search_results)24 25        # Get chunks26        all_chunks = extract_chunks(all_documents)27 28        # Generate embeddings for all chunks and the query.29        all_embeddings = self.embed_text(all_chunks)30        query_embedding = self.embed_text(query)[0]  # Single query embedding31 32        # Calculate cosine similarity between query and sentence embeddings, and select the top sentences.33        cosine_scores = np.dot(all_embeddings, query_embedding) / (34            np.linalg.norm(all_embeddings, axis=1) * np.linalg.norm(query_embedding)35        )36        top_k_indices = (-cosine_scores).argsort()[:topk]37        top_k_chunks = np.array(all_chunks)[top_k_indices]38 39        return top_k_chunks
Markdown Cell 014

The retriever determines the final chunks to return through three main steps.

  • First Step: The retriever takes the query, the search_results, and a variable topk (which determines how many chunks to return) as inputs. It then extracts chunks from the search_results.
  • Second Step: The extracted chunks are converted into embeddings using an embedding model. Since the chunks are in a list format, the embedding results will also be returned as a list. At the same time, the query is also converted into an embedding.
  • Third Step: Cosine similarity between the query’s embedding and the chunks’ embeddings is calculated to determine which chunks have the highest similarity to the query.

Through this process, our BaseRetriever retrieves and returns the topk chunks with the highest similarity.

II. Implementing a Reader

In this section, we will design the Reader.

What are the most important considerations when creating a Reader? The most crucial factor is likely the choice of LLM. Factors such as model size, performance on reasoning benchmarks, cost, and other considerations are typically part of the configuration.

However, since we have limited options for the LLMs we can use in this practice session, this will not be a consideration for us here.

So, what’s the next most important factor? Prompt design. It is well known that well-designed prompts lead to better results from the LLM.

Moreover, setting an appropriate prompt becomes even more critical for the CRAG dataset. In this task, the LLM must be able to answer “I don’t know” if it encounters something it is unsure about or cannot answer confidently. To achieve this, the prompt must be specifically designed to guide the LLM to behave in this manner.

Therefore, this exercise will be conducted in the following three main stages:

  • Design a Prompt Template
  • Implement a Prompt Generator
  • Implement a Reader
Markdown Cell 021

1. Design a Prompt Template

To design an effective prompt template, we need to carefully consider certain factors.

  • The response must be generated based on the given question and references.
  • In the CRAG benchmark, answers should not be too long or verbose. During evaluation, only the first 75 tokens are used for scoring, so the response needs to be concise.
  • The LLM must be able to recognize questions it cannot answer and respond with “I don’t know”.

Taking these factors into account, we can draft the following system_prompt:

Code Cell 022
1### YOUR CODE HERE ###2 3system_prompt = """4You are provided with a question and various references.5Your task is to answer the question succinctly, using the fewest words possible.6If the references do not contain the necessary information to answer the question, respond with 'I don't know'.7There is no need to explain the reasoning behind your answers.8"""
